## 1. 概要

webDeza は、販売を終えた「OPTPiX webDesigner」の代わりに使うことを目指す**画像編集ソフト**である。画像を開き、画像の全体か、矩形で選択した範囲に、ぼかしなどの処理をかける。切り抜き・回転・反転・画像サイズの変更もできる。仕上げた画像は、**ファイルサイズと画質を確かめながら**指定した形式で保存する。入力形式・出力形式・編集機能（フィルター）・キャンバスの道具を、後から足しやすい構成にすることを最も重視する。

切り抜きは、webDeza の編集機能の 1 つである。CoverCropper は、webDeza と同じ画像処理エンジンの切り抜きを「1024×768・JPEG 品質 85・表紙用の切り抜き」という固定の設定で使い、表紙の作成に特化させたものとする。CoverCropper の画面・操作・出力結果は今のまま変えない。

### 1.1 2 つのアプリの位置付け

| 項目 | CoverCropper（表紙の作成に特化） | webDeza（画像編集ソフト） |
|---|---|---|
| 目的 | ホームページの表紙画像をすばやく作る | 画像の編集と、Web 用の保存 |
| 画面 | 今の画面のまま | メニューバー・道具・画像ごとの子ウィンドウ・編集パネル・保存のダイアログ |
| 入力形式 | 固定（JPG / PNG / BMP / GIF / TIFF / WebP） | 形式プラグインに登録されたものすべて |
| 編集 | 枠の位置だけ | 矩形の選択範囲、フィルター（全体か選択範囲に。標準は ぼかし・基本補正）、切り抜き、回転・反転、画像サイズの変更、元に戻す / やり直し |
| 切り抜き | 常に 1024×768 の枠が出る | 編集機能の 1 つ。範囲を選択して、メニューから実行する |
| 出力 | JPEG・品質 85・1024×768 に固定 | 保存のダイアログで、形式・形式ごとのオプション・ファイルサイズの上限を選ぶ（大きさは、保存する前に編集の「画像サイズの変更」で変える） |
| ファイルサイズの確認 | なし | 保存のダイアログで、設定を変えるたびに保存サイズを表示。圧縮前後を並べて比べられる |
| 枚数 | 1 枚ずつ | 複数の画像を同時に開いて並べられる（編集するのは選んでいる 1 枚）。一括で保存できる |
| 画像処理 | 共通エンジン（固定の順番と値で呼ぶ） | 共通エンジン |

### 1.3 拡張のしかた

| 足したいもの | 実装するもの | 登録する場所 | 画面の変更 |
|---|---|---|---|
| 入力形式（例: カメラ RAW） | `IImageFormat` ＋ `IImageDecoder` | `FormatRegistry` | 不要。「開く」の種類の一覧と D&D の判定は登録内容から作る |
| 出力形式（例: WebP・AVIF の保存） | `IImageFormat` ＋ `IImageEncoder`（オプションは `ParameterDescriptor` で記述。サイズを調整できるパラメーターがあれば `SizeTuning` で宣言） | `FormatRegistry` | 不要。保存のダイアログの形式の一覧・オプションの入力欄・保存サイズの表示・ファイルサイズの上限は登録内容から作る |
| 編集機能（例: モザイク、ネガポジ反転、シャープ） | `IImageFilter`（パラメーターは `ParameterDescriptor` で記述） | `FilterRegistry` | 不要。メニューの「フィルター」と編集パネルに自動で並び、全体にも選択範囲にもかけられる。専用の画面が要るときだけ DataTemplate を足す |
| キャンバスの道具（例: 楕円の選択、文字入れ） | `ICanvasTool` | `ToolRegistry` | 不要。道具のボタンは登録内容から作る |

webDeza での登録は `WebDeza/Composition/AppModules.cs` の 1 か所にまとめる。外部ライブラリが要る形式（WebP や AVIF の保存など）は、別のプラグインプロジェクトにして、ここで登録する。

### 1.4 前提・制約

- 元画像を上書き・変更しない。元ファイルを開くのは形式レジストリ（`FormatRegistry.Decode`）だけとし、読み取り専用で開いて、読み終えたらすぐ閉じる。編集の結果は、保存で別のファイルにする。
- 外部と通信しない。
- エンジン・標準プラグイン・アプリ本体では、System.Drawing と外部の画像ライブラリを使わない（WPF / WIC と自前のピクセル処理だけ）。外部ライブラリが要る形式は、別のプラグインプロジェクトに閉じ込める。
- **編集は、実行したら確定する。** 開いている画像（メモリ上の画素）に処理をかけ、結果を今の画像にする。前の状態は履歴に残し、元に戻せる（F-07）。フィルターは、編集パネルで値を変えている間はプレビューを見せ、［適用］で確定する。2.3 までの「レシピから毎回作り直す非破壊編集」はやめた。
- 選択範囲は矩形だけとする（楕円・投げ縄などは 8 章の将来拡張）。
- **減色（GIF・PNG8 などの 256 色以下への変換）は行わない**。今の回線速度では必要性が低いため（2026-10-24 の判断）。
- CoverCropper の画面・操作・出力結果・設定とログの場所を変えない。CoverCropper の既存テスト（53 件）を書き換えずに通す（5.5）。
- 開いている画像と編集の内容は、アプリを終了すると消える（編集途中の状態を残す作業ファイルと、元のファイルへの上書き保存は 8 章の将来拡張）。

## 2. 機能要件（webDeza）

### F-01 画像を開く

| 項目 | 仕様 |
|---|---|
| 開き方 | ① メニュー［ファイル］→［開く…］ / ツールバーの［開く］ / `Ctrl+O`（OpenFileDialog、複数選択可） ② ウィンドウへのドラッグ＆ドロップ（ファイル・フォルダ、複数可） ③ コマンドライン引数（複数可） |
| 対応形式 | 形式レジストリに登録され、読み込みができる形式（標準は 5.4 の表）。「開く」の種類の一覧と D&D の判定は登録内容から作る |
| 形式の判定 | 拡張子で形式を選ぶ。標準プラグイン（WIC）は中身を見て判定するので、拡張子と中身が違っていても読める |
| OS のコーデックが要る形式 | WebP・HEIF・AVIF は、Windows に拡張機能が入っている場合だけ読める。読めないときは M01 に続けて M21（必要な拡張機能の名前）を出す |
| 複数ページ・複数フレーム | 1 枚目だけを使う（GIF は 1 フレーム目、TIFF は 1 ページ目、ICO はいちばん大きい画像） |
| 向き | EXIF などの向きの情報を読み込み時に反映し、正しい向きにする |
| 透過 | アルファを保つ（CoverCropper と違い、読み込み時に白で塗らない）。キャンバスでは市松模様の上に表示する。透過を保てない形式で保存するときだけ背景色で塗る（F-08） |
| 画素の形式 | すべて 8 bit の Bgra32（ストレートアルファ）に変換して扱う。16 bit などは 8 bit に落とす |
| DPI・色空間 | DPI は無視してピクセル数だけを扱う。ICC プロファイルによる色空間の変換はしない（どちらも CoverCropper と同じ） |
| 開いた後 | 画像ごとに子ウィンドウを 1 つ作り（F-02）、今回開いたうちの最後の画像を選ぶ。1 回に開く分は、フルパスの自然順（エクスプローラーと同じ `StrCmpLogicalW`）で順に開く |
| フォルダ | フォルダ直下の対応ファイルを開く（サブフォルダは見ない） |
| 重複 | 既に開いている画像とフルパスが同じもの（大文字小文字は区別しない）は開き直さず、その子ウィンドウを選ぶ。同時に開く画像の中の重複は 1 つにする |
| 上限 | 同時に開けるのは 50 枚まで。超えた分は開かず M15 |
| 非対応ファイル | 対応ファイルと混ざっている場合は除外し、M09 で件数を示す。1 件も対応していない場合は M01（フォルダだけを指定して画像が無い場合は M14） |
| D&D 中の表示 | 対応ファイルかフォルダを 1 つでも含む場合はハイライトして `DragDropEffects.Copy`、それ以外は `None` |
| 元ファイルのサイズ | 開くときに元ファイルのバイト数を覚えておく（保存サイズとの比率の表示に使う。F-09） |
| メモリ | 開いている画像は、すべてフル解像度でメモリに持つ（編集の結果がメモリにしか無いため）。足りなくなったら M02 |
| 大きすぎる画像 | 幅 × 高さ × 4 バイトが .NET の配列の上限（約 2 GB）を超える画像は M02 |
| 読み込みの失敗 | 子ウィンドウは作らず、M01 / M02 を出す。複数を開いたときは、読めたものだけを開き、読めなかったものをまとめて 1 回のダイアログで知らせる |

### F-02 画像のウィンドウ（複数の画像を並べる）

中央の領域（以下「ワークスペース」）に、開いた画像ごとの子ウィンドウを置く。編集するのは、選んでいる 1 枚（以下「アクティブな画像」）だけである。

| 項目 | 仕様 |
|---|---|
| 子ウィンドウ | タイトルバー（ファイル名・保存していない編集の印 `*`・［最大化 / 元に戻す］・［閉じる］）と、キャンバス（F-03）。最小化はしない |
| アクティブ | クリックした子ウィンドウがアクティブになり、いちばん手前に出て、タイトルバーの色が変わる。メニュー・ツールバー・道具・編集パネル・ステータスバーは、アクティブな画像を対象にする |
| 切り替え | クリック、`Ctrl+Tab` / `Ctrl+Shift+Tab`（開いた順）、メニュー［ウィンドウ］の一覧 |
| 移動・大きさ | タイトルバーのドラッグで移動、縁と角のドラッグで大きさを変える（最小 160×120 DIP）。タイトルバーがワークスペースの外に出ないようにする |
| 最大化 | タイトルバーのダブルクリックか［最大化］で、ワークスペースいっぱいに広げる。最大化している間は、どの画像に切り替えても最大化で表示する（1 枚ずつ見る使い方） |
| 新しく開いたとき | 最大化している間は最大化で開く。そうでなければ、前に開いた子ウィンドウから右下へ少しずつずらして置き（端まで来たら左上に戻る）、大きさは画像が全体表示で収まる大きさ（ワークスペースの 80% まで）にする |
| 並べ方 | メニュー［ウィンドウ］→［重ねて表示］（左上から少しずつずらす）、［並べて表示］（ワークスペースを格子に分けて、すべてが見えるようにする）。どちらも最大化を解く |
| ワークスペースの大きさが変わったとき | 最大化している子ウィンドウは追いかけて大きさを変える。それ以外は、タイトルバーが外に出たものだけ内側へ寄せる |
| 表示倍率 | 子ウィンドウごとに、別々の倍率と位置を持つ |
| 閉じる | ［閉じる］ / `Ctrl+W` / メニュー［ファイル］→［閉じる］。保存していない編集があれば M16 で確認する。［すべて閉じる］もある。**ファイルは削除しない** |
| 画像が無いとき | ワークスペースの中央に案内文「ここに画像やフォルダをドラッグ＆ドロップ、または［開く］」 |

### F-03 キャンバス（表示・ズーム・パン・道具）

| 項目 | 仕様 |
|---|---|
| 道具 | キャンバス左の縦のツールバーで切り替える（全画像で共通）。標準は「選択」（`M`・既定）と「手のひら」（`H`）。`Space` を押している間は一時的に手のひら。メニュー［選択範囲］→［領域選択］でも「選択」にする |
| 倍率の基準 | 100% = 画像の 1 px が画面の 1 物理ピクセル（高 DPI 環境でも等倍） |
| 全体表示 | 画像全体が収まる倍率。ただし 100% を超えて拡大しない |
| 範囲 | 最小は「全体表示の倍率」と 10% の小さい方、最大は 3200% |
| ズーム | マウスホイール（カーソル位置が中心）、`Ctrl++` / `Ctrl+-` とメニュー［表示］→［表示拡大］［表示縮小］（中央が中心）。1 段階 1.25 倍 |
| 全体 / 等倍 | `Ctrl+0` / ［全体表示］、`Ctrl+1` / ［100%］ |
| パン | 手のひらでドラッグ、中ボタンでドラッグ、`Space`+ドラッグ |
| パンの範囲 | 画像が領域より小さい向きは中央に固定。大きい向きは、画像の端が領域の内側に入り込まない範囲 |
| 子ウィンドウの大きさが変わったとき | 全体表示のときは全体表示し直す。ズーム中は倍率と表示の中心を保つ |
| 画像の大きさが変わったとき | 切り抜き・90° 回転・画像サイズの変更の後は、全体表示に戻す |
| 表示用画像 | 長辺が 4096 px を超える画像は、長辺 4096 px に縮小した表示用画像で表示する（編集と保存には使わない） |
| 補間 | 表示用画像の 1 px が 2 物理ピクセル未満なら `HighQuality`、それ以上なら `NearestNeighbor` |
| 透過 | 市松模様（8 DIP 角の明るい灰と白）の上に描く |
| 選択範囲の表示 | 選択範囲があるときは、その縁を白と黒の点線で描く（どの道具のときも）。枠の外は暗くしない。ハンドルは「選択」の道具のときだけ描く |
| フィルターのプレビュー | 編集パネルでフィルターの値を変えている間は、適用した結果を表示する（F-06） |
| 倍率の表示 | ステータスバーに表示（例: `37%`） |

### F-04 選択範囲と切り抜き

**選択範囲**

| 項目 | 仕様 |
|---|---|
| 形 | 矩形だけ。画像のピクセル座標（整数）で、常に画像の内側。画像ごとに 1 つ持つ（無いこともある） |
| 使い道 | フィルター（F-06）をかける範囲と、切り抜く範囲。選択範囲が無いときは、フィルターは画像全体にかかる |
| 作る | 「選択」の道具で、キャンバスをドラッグする（始めた点と今の点を対角にする矩形。画像の外へドラッグしたら端で止まる）。前の選択範囲は置き換わる |
| すべて選択 / 取り消し | `Ctrl+A` / メニュー［選択範囲］→［すべて選択］（比率が自由なら画像全体、比率が決まっていれば、その比率でいちばん大きい矩形を中央に置く）、`Ctrl+D` / ［選択の取り消し］。「選択」の道具で、選択範囲の外をドラッグせずにクリックしても解除する |
| 移動（マウス） | 選択範囲の内側をドラッグ（`SizeAll`）。大きさは変わらない |
| 移動（キー） | 矢印で 1 px、`Shift`+矢印で 10 px（「選択」の道具のとき） |
| 大きさ（マウス） | 比率が固定なら四隅のハンドル、自由なら四隅と四辺のハンドル。反対側の角（辺）を固定する。反対側を越えても裏返らず、最小（1 px）で止まる |
| 数値で指定 | 編集パネルの「選択範囲」に X・Y・幅・高さの入力欄。入力すると選択範囲が変わる（画像の内側に収める） |
| 比率 | 自由（既定） / 元画像と同じ / 1:1 / 4:3 / 3:2 / 16:9 / カスタム（幅:高さを 1〜10000 の整数で入力）。［縦横を入れ替え］で 4:3 ↔ 3:4 などにする。全画像で共通で、設定に保存する |
| 比率を変えたとき | 今の選択範囲は、中心を保って新しい比率に合わせる（画像からはみ出す場合は内側へずらし、収まらなければ小さくする） |
| 履歴 | 選択範囲の操作は履歴（F-07）に積まない。元に戻す・やり直しの後は、選択範囲を画像の内側に収め直す（収まらなければ解除） |

**切り抜き**

| 項目 | 仕様 |
|---|---|
| 操作 | メニュー［画像］→［選択範囲で切り抜き］ / `Ctrl+Shift+X` / 編集パネルの「選択範囲」の［切り抜き］。選択範囲が無いときは無効 |
| 内容 | 画像を、選択範囲の大きさに切り出す。切り抜いた後は選択範囲を解除し、全体表示に戻す |
| 履歴 | 1 段積む（元に戻せる） |

> 決まった大きさの画像（たとえば 1200×630）を作るときは、比率を 1200:630 にして範囲を選び、切り抜いてから、画像サイズの変更（F-05）で大きさを合わせる。

### F-05 回転・反転と画像サイズの変更

どれも画像全体が対象で、選択範囲には関係しない。それぞれ履歴に 1 段積む。

| 項目 | 仕様 |
|---|---|
| 回転 | メニュー［画像］→［右に 90° 回転］ / `Ctrl+R`、［左に 90° 回転］ / `Ctrl+Shift+R`。選択範囲は解除し、全体表示に戻す |
| 反転 | ［左右反転］・［上下反転］。選択範囲は、反転に合わせて位置を移す |
| 画像サイズの変更 | ［画像サイズ…］でダイアログを開く。幅と高さ（px。1〜30000、かつ幅 × 高さ × 4 が配列の上限以下）を入力する。「縦横比を保つ」（既定はオン）がオンなら、片方を入れるともう片方が決まる。今の大きさと、変更後の大きさ・倍率（%）を表示する。補間は Lanczos3。選択範囲は解除し、全体表示に戻す |

### F-06 フィルター

| 項目 | 仕様 |
|---|---|
| 一覧 | フィルターレジストリに登録されたフィルターを、登録順に、メニュー［フィルター］と、編集パネルの「フィルター」の選択欄に並べる。標準は「ぼかし」と「基本補正」。メニュー［フィルター］はサブメニューに分けず、登録したフィルターの後ろに、まだ無いフィルター（8 章）を無効の項目として並べる（作って登録したら、その無効の項目は外す） |
| 対象 | 選択範囲があればその範囲、無ければ画像全体。選択範囲にかけるときは、範囲の中の画素だけを材料にする（範囲の外の画素は、結果に混ざらない） |
| 操作の流れ | ① メニューか編集パネルでフィルターを選ぶ（メニューで選ぶと、編集パネルの「フィルター」がそのフィルターになる） ② 編集パネルの入力欄で値を変える。キャンバスにプレビューが出る ③ ［適用］で確定する（履歴に 1 段積む）。確定したら、入力欄は既定値に戻る |
| 入力欄 | フィルターのパラメーターの記述（`ParameterDescriptor`）から自動で作る（5.6）。スライダーはダブルクリックで既定値に戻す。［リセット］ですべて既定値に戻す |
| プレビュー | 値が既定値（`IsIdentity`）でない間、表示用画像の対象の範囲にフィルターをかけて表示する。スライダーの操作中は 50 ms 程度に間引いて更新し、止まったら必ず最後の値で更新する。半径などの長さを持つパラメーターは、表示用画像の縮小の割合に合わせて換算する（見た目を確定後とそろえるため） |
| プレビューの終わり | ［適用］・［リセット］・ほかのフィルターを選ぶ・ほかの画像に切り替える・その画像を編集する（切り抜き・回転など）で、プレビューをやめる。選択範囲を変えたときは、新しい範囲でプレビューし直す |
| 適用 | フル解像度の画像にかける。バックグラウンドで行い、その間は待機カーソル。値が既定値のときは［適用］を無効にする |
| 透過 | 基本補正はアルファを変えない。ぼかしはアルファもぼかす（透明な部分の色がにじまないよう、乗算済みアルファで計算する） |

標準フィルター「ぼかし」（ID: `blur`）:

| パラメーター | 範囲・既定 | 計算 |
|---|---|---|
| 半径 | 0〜100 px（0.5 刻み）・既定 0 | ガウスぼかし（標準偏差 = 半径 ÷ 2）を、箱形ぼかし 3 回で近似する（横・縦に分けて計算）。画像（選択範囲）の端は、端の画素を外へ延ばしたものとして計算する。0 のときは何もしない |

標準フィルター「基本補正」（ID: `basic`）:

| パラメーター | 範囲・既定 | 計算 |
|---|---|---|
| 明るさ | −100〜+100・0 | ガンマ補正。γ = 2^(−明るさ ÷ 100)、v' = 255 × (v ÷ 255)^γ。黒（0）と白（255）は変わらない |
| コントラスト | −100〜+100・0 | v' = (v − 127.5) × k + 127.5、k = 2^(コントラスト ÷ 100) |
| 彩度 | −100〜+100・0 | Y = 0.299R + 0.587G + 0.114B、C' = Y + (C − Y) × (1 + 彩度 ÷ 100)（C は R・G・B のそれぞれ） |

- 明るさとコントラストは実数のまま続けて計算し、1 回だけ四捨五入（`MidpointRounding.AwayFromZero`）して 0〜255 に収めた 256 段の LUT にする。彩度は LUT を適用した後の値から計算し、同じように丸める。

> ほかのフィルター（利用者がリストアップしたもの。4.3 のメニュー［フィルター］と 8 章）は、将来の拡張とする。足すときは `IImageFilter` を実装して登録するだけでよい。

### F-07 元に戻す・やり直し

| 項目 | 仕様 |
|---|---|
| 操作 | `Ctrl+Z` / メニュー［編集］→［元に戻す］ / ツールバー、`Ctrl+Y` または `Ctrl+Shift+Z` / ［やり直し］。メニューには操作の名前を出す（例: 「元に戻す: ぼかし」） |
| 対象 | 画像の中身を変える操作（フィルターの適用・切り抜き・回転・反転・画像サイズの変更）。選択範囲・表示倍率・保存の設定は対象外 |
| 範囲 | 画像ごとに別の履歴を持つ。アクティブな画像の履歴を使う |
| 1 回の単位 | 操作 1 回（［適用］1 回、メニューの実行 1 回） |
| 持ち方 | 選択範囲へのフィルターのように、画像の大きさが変わらず一部だけが変わる操作は、変わった範囲の前後の画素だけを持つ。画像全体が変わる操作は、前後の画像を持つ |
| 上限 | 画像ごとに 50 段まで、かつ履歴が持つ画素の合計 512 MB まで。超えたら古い段から捨てる（直前の 1 段は、512 MB を超えても残す） |
| 保存との関係 | 保存しても履歴は消さない。保存した時点まで元に戻す・やり直すと、「保存していない編集」の印は消える |

### F-08 保存の設定（保存のダイアログ）

保存の設定は、保存のダイアログで行う。メニュー［ファイル］→［保存…］ / ツールバーの［保存］ / `Ctrl+E` で、アクティブな画像を対象に開く。

| 項目 | 仕様 |
|---|---|
| ダイアログの構成 | 左にプレビュー（F-09）、右に設定と、保存サイズの表示。下に［保存］と［キャンセル］。大きさを変えられ、大きさは覚えておく |
| 形式 | 形式レジストリに登録され、保存ができる形式（標準: JPEG / PNG / BMP / TIFF）。既定は JPEG |
| 形式のオプション | 形式ごとのオプションの記述から入力欄を作る（標準は 5.4）。形式を切り替えても、それぞれの形式のオプションの値は覚えておく |
| 品質の決め方 | 形式がサイズを調整できる場合（標準では JPEG）、「品質を指定」と「ファイルサイズの上限を指定」から選ぶ。上限は KB で入力する（1〜1,000,000）。動作は F-09 |
| サイズ | 指定しない。今の画像の大きさのまま保存する（保存する大きさ（幅×高さ）は表示する）。大きさを変えるときは、保存する前に編集の「画像サイズの変更」（F-05）を使う |
| 背景色 | 透過を保てない形式で保存するとき、透過部分をこの色で塗る（既定は白）。色見本（白・黒・灰）と `#RRGGBB` の入力。透過を保てない形式を選んでいるときは M24 を表示する |
| メタデータ | 書き込まない（位置情報などの漏えいを防ぐ。CoverCropper と同じ） |
| 出力先 | フォルダのパス、［変更…］、［開く］（エクスプローラー）。CoverCropper の「保存先」と同じ扱い |
| ファイル名 | `{元のファイル名}_{yyyyMMdd_HHmmss}.{形式の拡張子}`。同名があれば `_2`, `_3` …（CoverCropper と同じ規則。拡張子だけ形式に合わせる）。保存するファイル名をダイアログに表示する |
| 設定の保持 | ダイアログは、前回［保存］を押したときの設定で開く。設定はファイルに保存する（F-12）。［キャンセル］で閉じたときは、変えた設定を捨てる |

> 利用者が決めた既定値でダイアログを開く機能と、設定に名前を付けて保存する機能（プリセット）は、将来の拡張とする（8 章）。

### F-09 ファイルサイズの確認

保存のダイアログで、設定を変えながら、保存したときのファイルサイズと画質をその場で確かめられるようにする。

| 項目 | 仕様 |
|---|---|
| 保存サイズの表示 | ダイアログに `保存サイズ 182.4 KB（元ファイルの 6%）` のように表示する |
| 計算のしかた | 実際に保存するのと同じ処理（5.8）で、メモリ上にファイルの中身を作り、そのバイト数を表示する。保存するときはその中身をそのまま書く（5.6）ので、**表示されるサイズは保存したファイルのサイズとバイト単位で一致する**（予想値ではない） |
| 計算のきっかけ | ダイアログを開いたときと、設定（形式・オプション・品質の決め方・背景色）を変えたとき |
| 計算の頻度 | スライダーなどの操作中は 200 ms ごとに間引いて計算し、操作が止まったら必ず最後の値で計算する。新しい計算を始めたら、古い計算の結果は捨てる |
| 計算中 | 「計算中…」と表示する。計算中でも［保存］は押せる（保存するときに必要なら計算し直す） |
| 速くする工夫 | 形式のオプションや品質の決め方だけが変わったとき（品質のスライダーなど）は、背景色で塗った後の画像を使い回し、エンコードだけをやり直す |
| 単位 | 1 KB = 1024 バイト。1 KB 未満は「B」、1 MB 未満は「KB」（小数 1 桁）、それ以上は「MB」（小数 2 桁）。ツールチップにバイト数をそのまま出す |
| プレビュー | ダイアログの左に、メモリ上に作ったファイルを読み直した画像（圧縮による劣化を含む）を表示する |
| 表示のしかた | 「並べて比較」（左: 圧縮前、右: 圧縮後。ズーム・パンは左右で連動）と「保存結果のみ」を切り替える。既定は並べて比較・倍率 100%。圧縮後の見出しに形式・使った品質・サイズを出す。比較のしかたは設定に保存する |
| プレビューの操作 | ズーム・パンは F-03 と同じ（道具は使わない）。設定を変えると、その場で圧縮後が更新される |
| ファイルサイズの上限 | 「ファイルサイズの上限を指定」のときは、上限以下になるいちばん高い品質を二分探索で探して使う（5.3）。見つけた品質を品質の入力欄とプレビューの見出しに表示する（例: 「品質 72 で 198.6 KB」） |
| 上限に収まらないとき | 品質をいちばん低くしても上限を超える場合は、いちばん低い品質で保存、M26 を出す |
| 一括保存での上限 | 画像ごとに品質を探す（画像によって品質が変わる） |

### F-10 保存

| 項目 | 仕様 |
|---|---|
| 操作 | 保存のダイアログの［保存］ |
| 内容 | 今の画像（編集を確定した結果の全体。選択範囲は関係しない）を、透過を保てない形式なら背景色で塗ってから、選んだ形式でエンコードする（5.8）。大きさは変えない。フィルターのプレビュー中の値は含めない |
| 書き込み方式 | 同じフォルダの一時ファイルに書いてからリネームする。既存のファイルは上書きしない。保存先が元画像と同じパスなら書かない（CoverCropper と同じ安全装置） |
| 出力先が未設定 / 存在しない | CoverCropper の F-04 と同じ（M05 / M06）。ダイアログは閉じない |
| 保存後 | ダイアログを閉じ、ステータスバーに M04。その画像の「保存していない編集」の印を消す。画像と履歴はそのまま |
| 失敗 | M07 を出し、ダイアログは閉じない |

> `Ctrl+S` は、将来の［上書き保存］（元のファイルに書く。8 章）に使うので、保存には使わない。

### F-11 一括保存

| 項目 | 仕様 |
|---|---|
| 操作 | メニュー［ファイル］→［すべて保存…］ / `Ctrl+Shift+E`。保存のダイアログが、一括保存用の形で開く（プレビューと保存サイズはアクティブな画像のもの。ボタンは［{n} 件を保存］） |
| 対象 | 開いているすべての画像（保存済みかどうかにかかわらず）。それぞれの今の画像を、同じ設定で保存する |
| 実行 | ［{n} 件を保存］を押すと、出力先を一度だけ確かめ（F-10 と同じ）、バックグラウンドで 1 件ずつ順に保存する（メモリを抑えるため並列にしない） |
| 進捗 | ダイアログに、プログレスバー・「3 / 20: photo.jpg」・［中止］ |
| 中止 | ［中止］ / `Esc`。保存中の 1 件は最後まで終えてから止め、M12 |
| 失敗 | ログに書き、次へ進む。失敗したときに出力先フォルダが無くなっていたら、残りも失敗するため止めて M06 |
| 完了 | ダイアログを閉じ、M11 を出す（失敗があれば警告アイコンで、失敗したファイル名を並べる）。保存できた画像の「保存していない編集」の印を消す |
| 実行中にできること | ［中止］だけ（ダイアログが開いている間、メインウィンドウは操作できない） |

### F-12 設定

| 項目 | 仕様 |
|---|---|
| 保存場所 | `%APPDATA%\webDeza\settings.json`。CoverCropper とは別 |
| 項目 | 出力先フォルダ、前回「開く」で使ったフォルダ、保存の設定（形式・形式ごとのオプション・品質の決め方と上限・背景色）、選択範囲の比率、メインウィンドウの位置・サイズ・最大化、保存のダイアログの大きさと比較のしかた |
| 形式 | `System.Text.Json`。パラメーターの値は「キー → 数値・真偽・文字列」の JSON オブジェクトで書く |
| 読み込みの失敗 | JSON が壊れているときは既定値で起動し、M20（CoverCropper と同じ） |
| 値の検証 | 登録されていない形式 ID（プラグインを外した場合など）は JPEG にして M25。オプション・上限・比率が範囲外なら、その項目を既定値にする。知らない項目は読み飛ばす |
| CoverCropper の設定 | 引き継がない（CoverCropper は自分用のツールで公開しないため）。webDeza は CoverCropper の設定ファイルを読まない |
| ログ | `%APPDATA%\webDeza\logs\app.log`（書式は CoverCropper と同じ） |

## 3. CoverCropper（簡易版）の仕様

### 3.1 位置付け

CoverCropper は、共通エンジンの機能を固定の設定・固定の順番で呼び、表紙の作成に特化させたアプリとする（以下、webDeza に対して「簡易版」とも書く）。画面・操作・メッセージ・設定とログの場所・出力結果は、CoverCropper 設計書のとおりで変えない。変えるのは、内部の処理を共通エンジンと共通ライブラリに任せることだけである（手順は 5.5）。

### 3.2 固定の設定

| 項目 | 固定値 | 実現のしかた |
|---|---|---|
| 入力形式 | .jpg .jpeg .png .bmp .gif .tif .tiff .webp | `AppConstants.SupportedExtensions`。形式レジストリのうち、この拡張子の形式だけを使う |
| 透過 | 白で塗る | エンジンの `Flatten`（読み込み直後） |
| リサイズの大きさ | 横 1024 基準。縦が 768 未満なら縦 768 基準（CoverCropper 設計書 F-02） | CoverCropper の `ImageResizer.CalculateSize`（今のまま。CoverCropper だけの計算なので、エンジンには入れない） |
| 補間 | Lanczos3 | エンジンの `Resize` |
| 切り抜き | 1024×768 | エンジンの `Crop` |
| 書き出し | JPEG・品質 85・メタデータなし | WIC プラグインの JPEG エンコーダーと `SafeFileWriter` |
| ファイル名 | `元名_yyyyMMdd_HHmmss.jpg` | `WebDeza.Core` の `OutputFileNamer`（拡張子 .jpg） |
| 処理の順序 | 読み込み → 白で塗る → 全体をリサイズ → 切り抜き → JPEG | CoverCropper の `MainViewModel`（今のまま） |

> CoverCropper で扱える形式を増やしたくなったら、`AppConstants.SupportedExtensions` の代わりに形式レジストリの一覧を使うだけでよい（今回はしない）。

| メニュー | 項目（キー） |

| ファイル | 新規画像作成…（`Ctrl+N`。将来） ／ 開く…（`Ctrl+O`） ／ 閉じる（`Ctrl+W`） ／ すべて閉じる ／ ― ／ 上書き保存（`Ctrl+S`。将来） ／ 保存…（`Ctrl+E`） ／ すべて保存…（`Ctrl+Shift+E`） ／ ― ／ 終了 |

- 「―」は区切りの線。「将来」は 8 章の将来拡張で、どんな機能が入るかが分かるように、作るまでは無効の項目として出しておく。
- メニューの項目とツールバーのボタンは、同じコマンドにつなぐ（無効になる条件も同じになる）。
- 機能を足すときは、メニューに項目を足す（将来の項目なら、無効の項目をコマンドにつなぐ）。フィルターと道具は、登録するだけでメニューとボタンに現れる。
- ［保存］は、今の画像を別のファイルに書く（元画像は変えない。F-10）。元のファイルに書く［上書き保存］は、1.4 を見直してからの将来拡張とする。
- ［画像］→［選択範囲で切り抜き］（画像を選択範囲の大きさにする）と、［編集］→［切り取り］（選択範囲をクリップボードに入れて、その範囲を消す。画像の大きさは変わらない）は別の操作である。

### 4.4 キーボードショートカット

メニューにあるもの（4.3）のほかに、次のキーがある。

| キー | 動作 |
|---|---|
| `Ctrl+Shift+Z` | やり直し（`Ctrl+Y` と同じ） |
| `Ctrl+Tab` / `Ctrl+Shift+Tab` | 次 / 前の画像をアクティブにする |
| `M` / `H` | 道具: 選択 / 手のひら（道具の登録内容に従う） |
| `←↑→↓` / `Shift`+矢印 | 選択範囲を 1 px / 10 px 移動（選択の道具のとき） |
| `Space`（押している間） | 手のひら |
| `Esc` | 一括保存を中止（保存のダイアログ） |

> テキスト入力欄・スライダー・コンボボックスにフォーカスがあるときは、修飾キーの無いキーはそのコントロールの操作を優先する。キャンバスをクリックすると、フォーカスはキャンバスに戻る。
> `+` / `-` はキーコード（`OemPlus` / `Add`、`OemMinus` / `Subtract`）で判定し、`Shift` の有無は問わない（日本語キーボードでは `+` を `Shift`+`;` で入力するため）。

**矩形の計算**（`CropFrameCalculator`。すべて純粋関数。選択範囲の操作に使う）

```
矩形の規則（FrameRules）を、画像のサイズ（W, H）・比率（AspectRatio? a）・最小の長さ（既定 1）から作る
  最大の矩形
    a なし                      → 画像全体
    W × a.H ≥ H × a.W           → 幅 = min(W, round(H × a.W / a.H))
    それ以外                    → 幅 = W
    高さ = HeightForWidth(幅) = min(H, round(幅 × a.H / a.W))     … round は AwayFromZero、整数演算で行う
  最小の矩形
    幅・高さとも「最小の長さ」以上（比率があるときは、幅 = max(最小の長さ, ceil(最小の長さ × a.W / a.H))、高さ = HeightForWidth(幅)）。最大を超える場合は最大に合わせる
```

| 関数 | 内容 |
|---|---|
| `Rules(W, H, AspectRatio? aspect, minLength = 1)` | 上の規則を作る |
| `Initial(rules)` / `Clamp(rect, rules)` / `Center(rect, rules)` | 最大の矩形を中央に / 大きさを最小〜最大・位置を画像の内側に / 大きさを保って中央へ |
| `FromDrag(startX, startY, endX, endY, rules)` | ドラッグの始点と終点を対角にする矩形（選択範囲を作る）。画像の内側に収め、比率があるときは比率に合わせる（始点を固定する） |
| `Move(rect, dx, dy, rules)` | px 単位で移動（画像の外には出ない） |
| `ResizeAroundCenter(rect, newWidth, rules)` | 中心を保って大きさを変える（比率を変えたときの合わせ直しに使う） |
| `ResizeFromHandle(rect, FrameHandle, pointerX, pointerY, rules)` | ハンドルのドラッグ。反対側を固定する |
| `Mirror(rect, horizontal, rules)` | 反転に合わせて位置を移す |

```csharp
public enum FrameHandle { TopLeft, Top, TopRight, Right, BottomRight, Bottom, BottomLeft, Left }
```

### 5.4 標準の形式プラグイン（WebDeza.Imaging.Wic）

| 形式 | ID | 拡張子 | 読み込み | 保存 | 透過 | 保存のオプション |
|---|---|---|---|---|---|---|
| JPEG | `jpeg` | .jpg .jpeg .jpe .jfif | ○ | ○ | × | 品質（Integer 1〜100、既定 85）。`SizeTuning("quality")` |
| PNG | `png` | .png | ○ | ○ | ○ | インターレース（Boolean、既定 オフ） |
| BMP | `bmp` | .bmp .dib | ○ | ○ | × | なし |
| TIFF | `tiff` | .tif .tiff | ○（1 ページ目） | ○ | ○ | 圧縮（Choice: なし / LZW / ZIP、既定 LZW） |
| GIF | `gif` | .gif | ○（1 フレーム目） | × | ○ | 減色をしないため保存は対象外 |
| JPEG XR | `jxr` | .jxr .wdp | ○ | × | ○ | |
| ICO | `ico` | .ico | ○（最大の画像） | × | ○ | |
| WebP | `webp` | .webp | △ | × | ○ | 要: 「WebP 画像拡張機能」 |
| HEIF | `heif` | .heic .heif | △ | × | × | 要: 「HEIF 画像拡張機能」（HEVC も） |
| AVIF | `avif` | .avif | △ | × | ○ | 要: 「AV1 Video Extension」 |

△ = Windows に拡張機能があるときだけ読める。登録は常に行い、読めなかったら `UnsupportedImageFormatException` にして `Requirement` を M21 に出す。

- **デコード**: `BitmapDecoder.Create(stream, PreservePixelFormat, OnLoad)` → 対象のフレーム → 向きを読む（CoverCropper と同じクエリ `/app1/ifd/{ushort=274}`・`/ifd/{ushort=274}`）→ `FormatConvertedBitmap` で Bgra32 → 256 行ずつ `ImageBuffer` へ写す（CoverCropper と同じく巨大画像の一時メモリを抑える）→ エンジンの `Orientation.ApplyExif`。
- **エンコード**: 不透明な画像は Bgr24、透過のある画像は Bgra32 にして WPF のエンコーダーに渡す。メタデータ（サムネイル・EXIF・カラーコンテキスト）は付けない。同じ画像・同じオプションなら、毎回同じバイト列になること（W09）。
- **表示用の変換**: `BitmapSourceConverter.ToBitmapSource(ImageBuffer)`（96DPI・Bgra32・Freeze 済み）と `FromBitmapSource(BitmapSource)`。

### 5.5 CoverCropper を簡易版にする

ファイルは移さず、CoverCropper の中のクラスをそのまま残して、中身だけを共通部品の呼び出しに置き換える。これで CoverCropper のコード・名前空間・テストに手を入れずに済む。

1. 画面（Views）・ViewModel・App・DialogService・Messages・AppConstants・Models（AppSettings・CropState）は変えない。
2. 画像処理の 4 つのクラスは、public API（インターフェース・メソッド・戻り値が Freeze 済み 96DPI Bgr24 の `BitmapSource` であること・例外の種類）を変えずに、中身を `WebDeza.Imaging` / `WebDeza.Imaging.Wic` の呼び出しに置き換える。

   | CoverCropper のクラス | 置き換え後の中身 |
   |---|---|
   | `ImageLoader.Load` | 拡張子を `AppConstants.SupportedExtensions` で確かめる → `FormatRegistry.Decode` → `Flatten(白)` → Bgr24 の `BitmapSource` |
   | `ImageLoader.ApplyOrientation`（public static） | エンジンの `Orientation` を使う（Bgr24 の配列を受け取る形は残す） |
   | `ImageResizer.CalculateSize` / `Resize` | CalculateSize は今のまま（CoverCropper だけの計算）。Resize は `Resize.Apply` |
   | `ImageCropper.Clamp` / `Center` / `Crop` | Clamp と Center は今のまま。Crop は `Crop.Apply` |
   | `JpegSaver.Save` | WIC プラグインの JPEG エンコーダー（品質は引数）＋ `SafeFileWriter` |

3. 設定・ログ・ファイル名の 4 つのクラスも、public API を変えずに中身を `WebDeza.Core` の呼び出しに置き換える。

   | CoverCropper のクラス | 置き換え後の中身 |
   |---|---|
   | `AppPaths` | `WebDeza.Core.AppPaths.GetDataFolder("CoverCropper")` |
   | `AppLog` | `WebDeza.Core.AppLog` に CoverCropper のログファイルのパスを渡して書く |
   | `SettingsService` | `JsonSettingsService<AppSettings>`（`LastLoadError` などの動作は今と同じ） |
   | `OutputFileNamer` | `WebDeza.Core.OutputFileNamer`（拡張子 .jpg） |

4. 引数なしのコンストラクターは残す。その場合は、WIC の形式を登録した既定の形式レジストリ（CoverCropper の中に 1 つ持つ）を使う。`App.xaml.cs` も既存テストも引数なしで作っているので、どちらも変えずに済む。
5. `CoverCropper.csproj` に `WebDeza.Imaging`・`WebDeza.Imaging.Wic`・`WebDeza.Core` への参照を足す。既存テスト（53 件）は書き換えない。`CoverCropper.Tests` は `CoverCropper` を参照したままにする（共通部品は推移的に参照される）。
6. 出力が変わらないことを確かめる。置き換えの**前に**、代表的な入力（横長・縦長・4:3・小さい画像・大きな拡大・透過 PNG・回転情報あり・パレット画像・16 bit グレースケール）で CoverCropper の処理結果を基準ファイルとして保存しておき、置き換えた後に比べる（R05）。基準ファイルは `CoverCropper.Tests/Baseline/`（作り方と中身は同じフォルダの README）、比べるテストは `BaselineRegressionTests`。入力は可逆の形式だけにし、JPEG 出力は OS のコーデックに左右されない形で比べる（README を参照）。

### 5.7 座標系と向き

| 名前 | 内容 | 使い道 |
|---|---|---|
| 画像 | 開いている画像の今の中身（向きを直した Bgra32。フル解像度）。編集を確定するたびに置き換わる | 編集と保存の対象。選択範囲の座標系（`PixelRect`） |
| 表示用画像 | 画像を長辺 4096 px 以下に縮小したもの。フィルターのプレビュー中は、それにフィルターをかけたもの | キャンバスの描画だけ |
| 保存する画像 | `ExportRenderer.Render` の結果（今の画像と同じ大きさ） | エンコードと、保存のダイアログのプレビュー |
| 画面 | DIP | マウス座標。`ViewTransform` で画像の座標と行き来する |

`ImageOrientation`（回転角 r と左右反転 f。適用の順序は「左右反転 → 回転」）と EXIF Orientation の対応:

| Rotation | FlipHorizontal | EXIF | 意味 |
|---|---|---|---|
| 0 | false | 1 | そのまま |
| 90 | false | 6 | 時計回り 90° |
| 180 | false | 3 | 180° |
| 270 | false | 8 | 反時計回り 90° |
| 0 | true | 2 | 左右反転 |
| 90 | true | 7 | 左右反転 → 時計回り 90°（反転置） |
| 180 | true | 4 | 上下反転 |
| 270 | true | 5 | 左右反転 → 反時計回り 90°（転置） |

- 読み込みのときは、EXIF の番号で `Orientation.ApplyExif` を呼ぶ。
- 回転・反転（F-05）は、今の画像に `Orientation.Apply` を 1 回かける: 右に 90° は (90, false)、左に 90° は (270, false)、左右反転は (0, true)、上下反転は (180, true)。

### 5.8 処理の順序

**開く**

```
元ファイル → FormatRegistry.Decode（向きを直した Bgra32） → 画像 → ImageHistory の最初の状態
                                                             └→ 長辺 4096 px 以下に縮小 → 表示用画像 → EditorCanvas
```

**編集の確定**（`DocumentViewModel.ApplyEditAsync`）

```
今の画像
  → 編集（バックグラウンド）
       フィルター   … RegionFilter.Apply(画像, 選択範囲, フィルター, 値, PixelScale = 1)
       切り抜き     … Crop.Apply(画像, 選択範囲)
       回転・反転   … Orientation.Apply(画像, 向き)
       画像サイズ   … Resize.Apply(画像, 幅, 高さ)
  → ImageHistory.Push(名前, 新しい画像, 変わった範囲)
  → 表示用画像を作り直す（大きさが変わったら ResetViewRequest++）
```

**フィルターのプレビュー**

```
入力欄の値の変更 → 50 ms ごとに間引く
  → 表示用画像（フィルター前）の、選択範囲に当たる範囲に RegionFilter.Apply
       PixelScale = 画像の幅 ÷ 表示用画像の幅（縮小していなければ 1）
       選択範囲は、表示用画像の座標に換算する（外側へ丸め、表示用画像の内側に収める）
  → 表示用画像（プレビュー）として EditorCanvas へ。古い計算の結果は捨てる
```

- フル解像度の画像にはかけない（確定するまで、画像も履歴も変わらない）。
- 表示用画像が縮小されているときは、プレビューと確定後の見た目が、画素の単位では一致しない（半径の換算と、範囲の端の丸めのため）。

**保存（1 枚・一括とも同じ）**

```
今の画像
  → ExportRenderer.Render          … 形式が透過を保てず、画像が不透明でないときだけ Flatten(背景色)
                                     ここまでが「保存する画像」（ExportPreviewService が使い回す）
  → ExportEncoder.Encode           … メモリ上にエンコード。上限があれば品質を探す
                                     ここまでが「保存サイズの表示」に使うバイト列
  → SafeFileWriter.Write           … そのバイト列を一時ファイル → リネーム。元画像のパスには書かない
```

**保存サイズの表示・プレビュー**（保存のダイアログ）

```
ダイアログを開く・設定の変更
  → 200 ms ごとに間引く
  → ExportPreviewService
       保存する画像の条件（画像・背景色・透過を保てるか）が前回と同じ → 保存する画像を使い回す
       違う → ExportRenderer.Render で作り直す
  → ExportEncoder.Encode → バイト数を表示
  → 同じ形式のデコーダーで読み直す → 圧縮後として表示
```

**CoverCropper（簡易版）**

```
元ファイル → FormatRegistry.Decode → Flatten(白) → ImageResizer.CalculateSize + Resize（全体） → Crop(1024×768) → JPEG(85) → SafeFileWriter
```

### 5.10 実装上の注意点

1. **元画像の保護**: 元ファイルを開くのは `FormatRegistry` だけにする。書き込みは `SafeFileWriter` だけにし、保護するパスに元画像を必ず渡す。CoverCropper の設定ファイルは読まない。
2. **非同期と古い結果の破棄**: 読み込み・編集の確定・表示用画像の作成・フィルターのプレビュー・保存サイズの計算・保存は `Task.Run` で行う。フィルターのプレビューと保存サイズの計算は、連番かキャンセルで「最後に頼んだもの」だけを画面に反映する。編集の確定は 1 つずつ行い、確定中はほかの編集を受け付けない。
3. **メモリ**: 開いている画像は、すべてフル解像度で持つ。8000×6000 では、画像 約 192 MB、表示用画像 約 64 MB（プレビュー中はもう 1 枚）、履歴は画像ごとに最大 512 MB を見込む。編集の確定中は、一時的に画像がもう 1〜2 枚分要る。`OutOfMemoryException` は捕まえて、読み込みなら M02、編集なら M28、保存なら M07 にする。一括保存は並列にしない。
4. **Resize の互換性**: CoverCropper の出力を変えないため、不透明な画像の計算（重みの作り方・足す順番・丸め）は CoverCropper の `ImageResizer.ResizePixels` と同じにする。
5. **保存サイズの一致**: 表示するサイズと保存したファイルのサイズを一致させるため、ファイルに書くのは必ず `ExportEncoder` が作ったバイト列にする（エンコーダーを直接ファイルに書かせない）。
6. **プラグインの例外**: フィルター・エンコーダー・デコーダーが投げた例外はアプリを落とさず、読み込みなら M02、編集の確定なら M28、保存なら M07、プレビューと保存サイズの計算なら表示を変えずに（サイズは「—」にして）ログに書く。
7. **キー操作とフォーカス**: ウィンドウの `PreviewKeyDown` で受け、4.4 の注記に従う。修飾キーの無いキーは、アクティブな画像の今の道具の `OnKeyDown` に先に渡す。メニューのショートカット（`InputGestureText`）は表示だけにし、実際のキーはウィンドウの `InputBindings` で受ける。
8. **高 DPI**: 100% の倍率は `VisualTreeHelper.GetDpi(this).DpiScaleX` から求め、`OnDpiChanged` で求め直す。
9. **起動**: `App.OnStartup` の最初に、ログ・設定の場所を `AppPaths.GetDataFolder(AppInfo.ProductName)` で決めてから、`AppModules.Register` で登録する。未処理例外の扱いは CoverCropper と同じ（タイトルは webDeza）。
10. **CoverCropper と同時に動かす**: 二重起動の禁止はしない。設定・ログが別なので同時に動かしてよい。
11. **子ウィンドウ**: 子ウィンドウの移動と大きさの変更では、キャンバスを描き直すだけにし、表示用画像は作り直さない。子ウィンドウを閉じたら、その画像・表示用画像・履歴への参照をすべて外す。

## 7. 受け入れ基準

## 9. Claude Code への実装指示（要約）

各段階の終わりに `dotnet build CoverCropper.slnx` と `dotnet test CoverCropper.slnx` が成功し、CoverCropper の既存テスト 53 件が書き換えなしで通ることを確かめる。段階 1〜5 は、2.3 までの設計で済んでいる。

1. **基準ファイルの作成**（済）: 置き換える前の CoverCropper で、5.5-6 の基準ファイルを作り、テスト用のデータとしてリポジトリに入れる。
2. **エンジン**（済）: `WebDeza.Imaging` を作り、`ImageBuffer`・基本の処理・パラメーター・フィルター（基本補正）・形式の仕組み・矩形の計算・`ExportEncoder`・`SizeTargetSearch`・`SafeFileWriter` を実装する。
3. **WIC プラグイン**（済）: `WebDeza.Imaging.Wic` を作り、5.4 の形式を実装する。
4. **Core と CoverCropper の載せ替え**（済）: `WebDeza.Core` を作り、CoverCropper の画像処理 4 クラスと設定・ログ・ファイル名の 4 クラスの中身を置き換える（5.5）。
5. **webDeza の土台**（済）: `WebDeza` とテストプロジェクトを作り、設定・1 枚の読み込み・キャンバスへの全体表示までを作る（2.3 の設計で、切り抜きの枠の表示まで作ってある）。
6. **編集の作り直し**: エンジンに `ImageHistory`・`Paste`・`RegionFilter`・`BlurFilter`・`ExportRenderer` を足し、矩形の計算を選択範囲用に直す。webDeza を `DocumentViewModel` と選択範囲の形に載せ替え、切り抜きの枠の常時表示をやめる。使わなくなったもの（`EditRecipe`・`RenderPipeline`・`EditHistory`・`CropAspect`・`ExportPreset`・`OutputSize`）を消す。
7. **画面の骨組み**: メニューバー、ワークスペースと子ウィンドウ、複数の画像を開く、`FileCollector`、D&D とコマンドライン引数（F-01、F-02）。
8. **キャンバスと道具**: `ViewTransform`・ズーム・パン・道具の仕組み・選択と手のひらの道具・選択範囲の比率（F-03、F-04 の選択範囲）。

11. **仕上げ**: 拡張の確認（テスト用の形式とフィルターを `AppModules` に足すだけで動くこと）、CI に webDeza の配布用ビルドと成果物（`webDeza-win-x64`）を足す、README に webDeza の説明を足す。
12. 元画像に書き込むコードパス、CoverCropper の設定ファイルに書き込むコードパスが無いことをレビューで確かめ、7 章の受け入れ基準を確かめる。
